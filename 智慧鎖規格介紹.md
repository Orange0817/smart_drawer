# RFID Access Control
An ESP32-based RFID smart drawer lock using an RC522 RFID reader, 0.96-inch OLED display, servo motor, tactile button, and LED.

The system uses RFID card authentication to control the drawer lock. When an authorized RFID card is detected, the servo motor unlocks the drawer. After the drawer is returned to its original position, the user must press the button to lock it again.

If the drawer remains unlocked for more than 30 seconds, the LED turns on to remind the user that the drawer has not been locked.

The system also provides a web-based administrator interface hosted on XAMPP. Administrators can register and manage RFID cards through the web interface. RFID card information is stored in a MySQL database and synchronized to the ESP32. The ESP32 stores the synchronized authorized card list locally using the Preferences library.


---
## Features
- RFID card authentication
- Authorized RFID card management
- Dynamic RFID card storage
- Support for up to 5 authorized RFID cards
- OLED status display
- Servo motor control for drawer locking
- Physical button for re-locking
- 30-second unlocked warning
- LED warning indicator
- ESP32 local non-volatile card storage
- Administrator web interface
- XAMPP-based RFID card management
- MySQL database for RFID card information
- Serial communication between the management system and ESP32
- RFID card registration mode
- 20-second RFID card registration timeout

- Jumper Wires
- USB Power Cable

## Web-Based RFID Card Management
The smart drawer system is extended with a web-based administrator interface hosted using XAMPP.
The administrator can access the management webpage to register and manage authorized RFID cards. Card information is stored in a MySQL database instead of being permanently hard-coded in the ESP32 program.

## Administrator Management System
The administrator webpage provides a centralized interface for managing registered RFID cards.
The administrator can:
  - Add a new RFID card
  - View registered RFID cards
  - Edit card information
  - Delete an RFID card
  - View the registration status of RFID cards
  - Synchronize authorized RFID cards with the ESP32

## Database Design

### rfid_cards Table Structure:
| Field | Data Type | Description |
|-------|-----------|-------------|
| id    | INT       | Primary Key, Auto Increment |
| user_id | INT       | Foreign Key referencing the users table |
| card_uid | varchar(32)   | Unique identifier for the RFID card |
| card_name | varchar(50) | Name or label for the RFID card |
| created_at | timestamp | Timestamp of when the card was registered |
| updated_at | timestamp | Timestamp of when the card was last updated |

### users Table Structure:

| Field | Data Type | Description |
|-------|-----------|-------------|
| id    | INT       | Primary Key, Auto Increment |
| username | varchar(50) | Username for the user |
| password | varchar(255) | Hashed password for the user |
| created_at | timestamp | Timestamp of when the user was created |

## RFID Authentication Flow
When a user scans an RFID card, the ESP32 reads the card UID using the RC522 reader and compares it with the authorized RFID card list stored locally on the ESP32.

```text
RFID Card
    ↓
RC522
    ↓
ESP32 Reads UID
    ↓
Compare with Authorized Card List
    ↓
 ┌──────────────────────┐
 │                      │
 ▼                      ▼
Authorized            Unauthorized
 UID                     UID
 │                        │
 ▼                        ▼
Servo Unlock          Keep Locked
 │                        │
 ▼                        ▼
OLED: "Unlocked!"     OLED:
OLED: "Welcome"       "Access Denied"
                         │
                         ▼
                      OLED:
                      "Invalid Card"
```
The authorization information is managed through the administrator webpage and stored in the MySQL database. After synchronization, the authorized RFID card UIDs are stored locally in the ESP32 using the Preferences library, and RFID authentication is performed locally by the ESP32.
